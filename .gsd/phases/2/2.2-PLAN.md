# Phase 2.2: Checkout & Registration Flow Parity

## Objective
Implement exact simulator visual parity for the registration checkout flow, including single and bundle registrations, duration selection, commit/reveal delays, and payment.

## Context
The current `beginRegistration` and `commit` functions in `live-adapter.ts` throw up a generic prompt using `asWindow.openModal`. The simulator has a highly detailed, multi-step registration wizard with progress bars, cost breakdowns, and 60-second commit delay visuals.

## Tasks

1. **Single Name Checkout Flow (DLY-009→DLY-018, UX-120→UX-121)**
   - Intercept the "Register" button to trigger the simulator's exact registration wizard screen.
   - Bind the duration selector (1-10 years) to the exact HTML dropdown/slider.
   - Wire the "Commit" button to trigger the smart contract commit, and transition the simulator wizard to the waiting/countdown state.
   
2. **Commit/Reveal UX (UX-122)**
   - Implement the exact 60-second visual countdown defined in the simulator.
   - Enable the "Reveal and Pay" button exactly when the commitment matures.
   - Bind the final transaction success to the simulator's exact success screen.

3. **Bundle Registration Checkout**
   - Bind the "Continue with Selected" behavior to the simulator's multi-name checkout view.
   - Replicate the bundle discount logic visually in the cost breakdown precisely as styled.
   - Wire the batch commit and bundle-reveal functions to the simulator's multi-item wizard.

## Verification
- Search for a name, select it, and register it via the UI.
- Confirm the wizard steps, styles, typography, and countdown match the simulator exactly.
- Complete a multi-name bundle registration through the UI.
