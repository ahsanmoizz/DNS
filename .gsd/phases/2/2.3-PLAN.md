# Phase 2.3: Name Management & Renewal Parity

## Objective
Map the record editor and domain renewal workflows from generic modals to the exact simulator Dashboard/Management views.

## Context
The current `openLiveName` generates a giant block of generic HTML inputs inside a generic modal. The simulator contains an elegant Name Dashboard with tabs for Address, Multichain, Profile, Content, and Subnames.

## Tasks

1. **Domain Dashboard View (DLY-023)**
   - Wire the "Manage" button in the portfolio to open the simulator's exact Domain Dashboard view.
   - Populate the header, current owner, and resolver fields into the simulator's exact DOM structure.

2. **Record Editors (DLY-025→DLY-030, UX-127→UX-128)**
   - Map `contracts.setAddress` to the simulator's ETH address input.
   - Map `contracts.setContenthash` to the simulator's guided website/dApp forms (UX-128).
   - Implement the simulator's avatar/bio/website treatment (UX-127) calling `contracts.setText` instead of the generic key-value fields.

3. **Renewal Flow (DLY-019→DLY-020, UX-125, UX-162→UX-165)**
   - Wire the simulator's renewal slider/duration picker.
   - Implement the multi-domain bulk-renewal flow (expiring-first sorting, locked totals) exactly as presented in the simulator HTML.

## Verification
- Open a registered name and verify the Dashboard tabs match the simulator.
- Modify records and renew the name via the simulator UI.
- Verify bulk renewal functionality and styling.
