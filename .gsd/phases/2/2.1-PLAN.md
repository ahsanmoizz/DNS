# Phase 2.1: Core Identity, Portfolio & Search Mapping

## Objective
Implement exact simulator visual parity for wallet connection, the portfolio dashboard, and name search, replacing generic adapter modals with the simulator's built-in HTML UI states.

## Context
The current `live-adapter.ts` injects its own HTML strings and uses a generic `openModal` wrapper. To pass the Phase 7 Visual Parity Audit, the adapter must directly drive the elements inside `Daily_User_Marketer_Simulator_V3_6.html`.

## Tasks

1. **Wallet Connection Parity (DLY-001, DLY-002)**
   - Analyze simulator HTML for the connect-wallet button states (default, connecting, connected with balance/address).
   - Update `live-adapter.ts:connectWallet` to toggle the exact simulator DOM classes and text content instead of just setting `textContent`.
   
2. **Portfolio Dashboard Integration (DLY-003, DLY-024, DLY-034)**
   - Inspect the simulator HTML for the "My Names" tab structure (`ownedNamesList`).
   - Rewrite `loadLivePortfolio` to clone and populate the simulator's exact row templates for owned names, expiry dates, and activity logs.
   - Map the empty states to exactly match the simulator's beautiful empty state.

3. **Name Search Parity (DLY-004→DLY-008, UX-119)**
   - Find the exact search input and result grid in the simulator HTML.
   - Update `searchAll()` and `renderSelection()` to populate the existing simulator rows, including exact availability, reserved, and premium styling classes (e.g., matching the simulator's SVG icons and button variants).
   - Ensure label safety warnings (invalid characters) render in the exact inline simulator location, not as a generic modal.

## Verification
- Run `pnpm dev` for `user-web`.
- Verify the wallet connection flow matches the simulator EXACTLY.
- Verify search results look indistinguishable from the simulator.
