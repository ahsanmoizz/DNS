# Plan 1.1: Local Scripts & PM2 Configuration

<objective>
Establish the local build script, deployment script, and PM2 process configuration for the slim transfer deployment.

Purpose: Automates compiling the app and copying it to the server without needing Docker locally or build tools on the server.
Output: `.env.example`, `scripts/build.sh`, `scripts/deploy.sh`, `ecosystem.config.cjs`
</objective>

<context>
Load for context:
- .gsd/SPEC.md
- .gsd/DECISIONS.md
- docker-compose.yml (for reference)
</context>

<tasks>

<task type="auto">
  <name>Create .env.example with correct offset ports</name>
  <files>.env.example</files>
  <action>
    Create `.env.example` based on the existing `.env`, but explicitly define the offset ports decided in Phase 1 (PostgreSQL=5480, Redis=6380, API=4100, User=3100, Admin=3101, Preview=3102).
    Remove actual secrets, replacing them with placeholders.
    AVOID: Including actual private keys or the real JWT secret in `.env.example`.
  </action>
  <verify>grep 5480 .env.example</verify>
  <done>.env.example contains all required environment variables with offset ports.</done>
</task>

<task type="auto">
  <name>Create PM2 ecosystem config</name>
  <files>ecosystem.config.cjs</files>
  <action>
    Create `ecosystem.config.cjs`.
    Define processes: `daily-api` (runs API), `daily-indexer` (runs indexer), and `daily-mail-relay` (runs mail relay).
    Note: The static frontends (user-web, admin-web) are explicitly owned and served by Nginx. PM2 manages ONLY the backend Node services.
  </action>
  <verify>node -c ecosystem.config.cjs</verify>
  <done>ecosystem.config.cjs is syntactically valid and defines the required processes.</done>
</task>

<task type="auto">
  <name>Create build and deploy scripts</name>
  <files>scripts/build.sh, scripts/deploy.sh</files>
  <action>
    Create `scripts/build.sh` that runs `pnpm install --frozen-lockfile` and `pnpm build` across the workspace.
    Create `scripts/deploy.sh` that accepts an SSH target (e.g., user@host). It should package the necessary slim artifacts (dist folders, api/indexer source/dist, package.json, workspace yaml, ecosystem.config.cjs, scripts, .env) into a tarball, `scp` it to the target, and extract it to a target directory.
    Make both scripts executable.
    AVOID: Hardcoding the SSH target or copying `node_modules` from local to remote (since native binaries might mismatch). The deploy script should trigger a targeted `pnpm install --prod` on the server or use slim transfer. Wait, ADR-007 says slim transfer includes `node_modules`. If so, copy local `node_modules` but warn or exclude native-only if necessary, or just tar everything up.
  </action>
  <verify>chmod +x scripts/build.sh scripts/deploy.sh && bash -n scripts/build.sh && bash -n scripts/deploy.sh</verify>
  <done>build.sh and deploy.sh are created and executable.</done>
</task>

</tasks>
