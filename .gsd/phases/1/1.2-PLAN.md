# Plan 1.2: Server Setup Script

<objective>
Create the server-side setup script that connects to existing PostgreSQL and Redis prerequisites, configuring the process manager to serve the deployed application.

Purpose: Automates the transition from a fresh artifact upload to a running, isolated production application on a server with existing infrastructure.
Output: `scripts/setup.sh`
</objective>

<context>
Load for context:
- .gsd/SPEC.md
- .gsd/DECISIONS.md
- deploy/nginx-user.conf
- deploy/nginx-admin.conf
</context>

<tasks>

<task type="auto">
  <name>Create setup.sh script</name>
  <files>scripts/setup.sh</files>
  <action>
    Create `scripts/setup.sh`.
    The script should:
    1. Read `.env` variables securely.
    2. Connect to existing PostgreSQL running on the offset port `5480` and create the database (`daily_identity`) and user if they don't exist via `psql -p 5480`. Assume Redis is managed identically via offset ports.
    3. Copy Nginx configs (`deploy/nginx-*.conf`) to `/etc/nginx/sites-available/` and symlink to `sites-enabled/` (or `conf.d/`), modifying paths to point to the correct deployment directory instead of `/usr/share/nginx/html`.
    4. Run `pnpm install --frozen-lockfile` to ensure any native modules are rebuilt for Linux.
    5. Run the database migrations via `pnpm --filter @daily/api tsx src/migrate.ts`.
    6. Start PM2 via `pm2 start ecosystem.config.cjs && pm2 save`.
    Make the script executable.
    AVOID: Destructive operations. Use `IF NOT EXISTS` for database operations. Ensure the Nginx reload handles failures gracefully (e.g., `nginx -t`).
  </action>
  <verify>chmod +x scripts/setup.sh && bash -n scripts/setup.sh</verify>
  <done>setup.sh is created, executable, and contains all required steps.</done>
</task>

</tasks>
