## Overview

Daily Identity is a decentralized domain-name identity system built on Ethereum (Sepolia testnet). Users register `.dly`, `.day`, and `.daily` names as ERC-721 NFTs, manage DNS-like resolver records, send encrypted mail addressed to names, receive Paid Attention marketing rewards, and store encrypted evidence on Google Drive. An admin panel provides protocol governance, campaign moderation, mail relay controls, and operational monitoring.

The architecture is a **simulator-first** design: two large standalone HTML simulator files (User: 304KB, Admin: 117KB) define the full UX specification. Vite-powered live-adapter TypeScript modules are injected at runtime to replace simulated behavior with real blockchain + API calls. A 200-feature register (DLY-001→UX-200) tracks parity between simulators and live implementation.

## Data Flow

### 1. User Registration Flow
```
Browser → MetaMask wallet → commit() → wait 60s → register() → NameRegistered event
  → Indexer picks up event → indexed_events table
  → API /v1/names/:name reads on-chain state via SDK
```

### 2. Encrypted Mail Flow
```
Sender → SDK.encryptForRecipient(recipientPublicKey) → ciphertext
  → POST /v1/mail/envelopes (EIP-712 signed envelope)
  → API validates signature + on-chain mailbox state
  → Stores ciphertext reference in mail_messages table
  → Recipient → GET /v1/mail/:namehash → SDK.decryptForRecipient(privateKey)
```

### 3. Paid Attention Campaign Flow
```
Marketer → POST /v1/marketing/campaign-quote (validates audience, checks escrow)
  → CampaignEscrow.fund() on-chain (locks ETH)
  → POST /v1/marketing/campaigns (verifies CampaignFunded event on-chain)
  → Admin reviews → POST /v1/admin/campaigns/:id/review
  → Admin delivers → distributes to eligible consent addresses
  → Recipients engage → EIP-712 signed engagement receipts
  → Merkle-tree reward distribution → on-chain claims
```

### 4. CCIP Off-Chain Resolver
```
External ENS lookup → Resolver.resolve() reverts with OffchainLookup
  → Client calls POST /v1/ccip/resolve
  → API signs result with CCIP gateway key
  → Client submits signed result back to resolver
```

## Conventions

**Naming:** camelCase for TypeScript identifiers, snake_case for SQL columns, PascalCase for Solidity contracts and events.
**Structure:** pnpm workspace monorepo with `apps/`, `packages/`, `services/` separation. Root-level simulators serve as the canonical UX specification.
**Authentication:** Wallet-based (EIP-191 signature + ERC-1271 fallback), JWT session tokens via `@fastify/jwt`.
**Validation:** Zod schemas at every API boundary with strict parsing.
**On-chain interaction:** `ethers v6` throughout, EIP-712 typed data for all signed messages.
**Testing:** `node --test` (Node.js built-in test runner), `tsx --test` for TypeScript tests, `truffle test` for contracts.
**Deployment:** Docker Compose with migration-first startup (migrate → api → indexer → frontends).
